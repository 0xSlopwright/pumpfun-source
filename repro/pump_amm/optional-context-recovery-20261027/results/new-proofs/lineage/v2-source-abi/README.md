# V2 Context module control and orderable refinement

The original three V2 instruction wrappers build a 40-byte `Context`: program id, accounts pointer, parser-updated remaining-account slice, and two bump bytes. The handlers read only accounts at offset 8 and event-authority bump at offset 33. The old private `trade.rs` implementations were promoted to those two arguments, so the wrappers omitted 88 bytes of construction. No omitted runtime field use was found.

Actual-Anchor direct objects reproduce both ABIs: a private module gives an accounts pointer and one byte; a narrow public module re-export preserves the full Context. The source control moves the three unchanged V2 bodies into their evidenced `instructions/swap/trade_v2.rs` module and narrowly re-exports that module. Existing call paths use their existing compatibility glob. No new inlining attribute, artificial field or diagnostic coordinate is added.

The valid full control is `3c263d0dbc5422c0c191842527df4da562a905511411b0b8c256316fee8600be`: **649/785 normalized, 148 raw**. All three original 1,064-byte V2 wrappers match, but exposing the module also exposes `BuyResult::total_user_quote`. That changes its scalar ABI to a 96-byte result reference and inserts a copy into the formerly matched preview helper. The sole loss is `0x565e8`. This is a preserved negative control, not a selected candidate. The initial failed parse-only build and source are also retained: the extraction left a documentation comment behind, corrected by moving it with its function.

`recovery-refined.patch` is the orderable patch against frozen joint `0881a95d…`. It additionally marks only `BuyResult::total_user_quote` as `pub(crate)`, preserving its previously effective visibility. The one-line follow-up alone is `preview-visibility.patch`. The refined source is **not full-built here**. Direct objects with multiple natural callers confirm the method ABI: private takes two scalar values, public takes the full result reference, and their sizes differ by 16 bytes. Those objects are 624/640 bytes because of the external-crate error path; the full-program methods are 600/616. Neither object is claimed to match the full original body.

All 65 focused buy, sell, context and executor cases pass on the valid full negative control, with 130 verified signatures, matching logs/errors and context before/after state. The valid build binds 227 inputs and 762 unchanged dependency artifacts. Full integrated build/recount and broader acceptance of the refined patch remain with the root/reviewer batch.

Portable saved verification: `python -B verify.py --root REPOSITORY`. Runtime replays are `run65.py --inputs INPUT_ROOT --candidate ELF --output NEW_DIRECTORY`; offline replay verification is `verify65.py --inputs INPUT_ROOT --candidate ELF --reports DIRECTORY`. The frozen input root used here is included as `runtime-inputs/`.
