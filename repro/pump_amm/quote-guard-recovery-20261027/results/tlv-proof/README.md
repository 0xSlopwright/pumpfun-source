# Independent transfer-fee TLV corpus

This saved runtime packet contains 876 deterministic cases, executed separately against the deployed original AMM and three source-built candidates. It includes the published 5cd baseline, semantic decoder fix7673, and final integrated5c1e candidate. No parser or application source was edited by this worker.

The baseline differs in 430 cases: 80 log-only differences and 350 involving other result fields. Both fixed and integrated candidates have zero differences. Each run retains 1,752 signed transaction receipts, full logs and complete non-executable transaction-message account snapshots. Executable account metadata is captured separately; its program-account balances depend on ELF size, and the loaded program hashes are independently bound by the observer. The verifier authenticates all three runs (5,256 signature checks) and checks identical signed inputs/prestates across all six executions per case.

Coverage includes 13 groups: exact account-size boundaries (including355), declared versus actual fee extents, unknown extension IDs and payloads, duplicate fee/unknown extensions, embedded headers, zero terminators and partial headers, trailing bytes, skipped payloads up to65,535bytes, envelope byte mutations, fee limits, deterministic bit mutations, and 48 successful old/new epoch-selection cases spanning all three trade routes. Some malformed envelope cases reject before the custom parser; successful and rejected outcomes remain explicit in the reports. This is a bounded local differential corpus, not exhaustive Token-2022 or whole-program equivalence.

`verify_bundle.py --expected-seal SEAL` verifies all packet hashes, program identities, signatures, full normalized results/logs, account snapshots, and cross-run inputs. It executes no compiler, VM or network. Runtime-produced reports are preserved compressed without rewriting. The normalizer removes only complete compute-consumption log lines and diagnostic source coordinates. The older stopped snapshot experiments are outside this packet and are not counted.

The original program is identified by its retained deployed SHA-256. Candidate binaries are included for direct identity checks; their source/build provenance belongs to their owning reconstruction checkpoints. Re-running the original producer requires the repository fixtures/dependencies and Solders runtime. Saved verification uses the included inputs and Solders without the original work paths.
