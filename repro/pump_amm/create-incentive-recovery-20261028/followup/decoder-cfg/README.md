# Decoder CFG and dataflow review after H15

The frozen e33e decoder is 656 bytes; original `0xf31d8` is 664. Both contain no calls or data relocations. The net extra original instruction is the unconditional branch at `+656` (`0xf3468`) from the out-of-line fee payload block back to cursor advancement at `+480` (`0xf33b8`). The candidate payload falls through into its advancement block at `+608`. The original has nine unconditional branches and the candidate eight. The different early-return and TLV-tail placements exchange other jumps without changing that net count.

`analysis.json` contains a symbolic comparison of all 22 paired control-flow cutpoints. The verifier interprets every instruction between them, preserving 64-bit arithmetic expressions, branch conditions, ordered memory reads/writes and destination cutpoints. All register effects and ordered memory effects agree. The only predicate transformations are inversion of the same equality/range conditions. The setup independently initializes the cursor and fee tag in opposite order. No guard, return-tag, cursor-overflow, fee-field, or input/output memory-access difference was found within the modeled ABI.

The parser checks the same 82-byte legacy form, minimum 167-byte extended form, 83 zero padding bytes, mint-account byte, zero TLV terminator, four-byte header, bounded entry size, duplicate fee entry and minimum 108-byte fee payload. Both read old fee fields at header offsets 76/84/92 and new fields at 94/102/110, spill the same six values, and serialize the same 56-byte native result. Absent fee payload bytes are inactive and may originate from uninitialized stack storage in either machine body; this review does not turn them into a Rust initialization guarantee.

This is a structural block-bisimulation result with explicitly paired cutpoints and valid memory accesses. It is not normalized instruction equality, whole-program equivalence, proof of behavior for forged Rust ABI inputs, or recovery of historical source spelling. The matching earlier object body is included only to bind the saved LLVM IR to this linked decoder; its IR contains no branch-profile annotation in the decoder. The original branch probabilities or source block order are not authenticated.

No source patch or build was justified. The previously tested shrinking-slice, explicit-arm, common-break and nested-Option variants remain negative controls in the separate decoder-owner proposal packet. No padding, forced attributes or repeat syntax trial was added. The next independent source-recovery lane is the missing seven-Pubkey serializer boundary.
