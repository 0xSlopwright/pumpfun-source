# Multihop flags collector: refreshed ABI and caller audit

Original `0xfb08/704` has exactly one direct incoming call: `0x3f2c8`, inside the multihop coordinator at `0x3dbc0 + 0x1708`. The only outgoing call is `0x111348/24`, the allocation-error handler. There are no Source records in the helper.

The caller creates a 32-byte iterator carrier at stack -344: a reference to the direction Boolean at -592, a reference to the total hop count at -656, followed by start and end usize values. The helper reads offsets 0/8/16/24 and returns Vec capacity/pointer/length through r1. The collector allocates exactly the nonnegative range length through the standard bump allocator and writes one byte per hop. Its truth table uses bit0 for protocol and bit1 for creator: for buy, first gets protocol and last gets creator; for sell, last gets protocol and first gets creator. These names describe the observed truth table, not recovered historical Rust variable names.

The prior tuple/iterator object control already recovers the complete 704-byte size. Its six differing instruction slots at +328 through +368 move two reference loads ahead of the bump-allocator cursor store; the original performs the cursor store first. The new audit checks all six differences and every incoming call against the frozen e33e artifact, then reruns the existing 200-case bounded instruction interpreter over original and object code. Counts 0/1/2/3/255/u64-max, both directions, range tails and heap exhaustion are covered. This is instruction interpretation with a bounded memory model, not a Solana runtime replay.

The current source performs the same map/collect expression within the multihop coordinator but emits no matching separate helper. The old local `is_buy` trial and tuple-shape variants are not new recovery evidence; no repeated compile was made. The remaining distinction is compiler alias/placement and the monomorphized collector boundary. A new helper, forced attribute or API solely to obtain the size is not justified. No source patch is proposed.
