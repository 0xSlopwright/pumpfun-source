# External fee CPI carrier review after H15

Original selector `0x13458` is 2,264 bytes with eleven direct calls. The e33e selector at `0x23228` is 2,248 bytes with twelve. Its additional call is a 184-byte memcpy at `+1512`, after successful market-cap validation and before the generated fee CPI. It copies an already-constructed CpiContext from stack -400 to outgoing storage at -184. Original constructs the same carrier at -288 and passes that storage directly.

The generated `get_fees_with_quote_mint` body is 3,200 bytes and matches the original complete normalized instructions and relocation pattern. The 600-byte context destructor also matches. The active cached Anchor generator takes CpiContext by value; its normal Rust indirect argument uses a pointer. Both callers preserve the same early AccountInfo clones and pass the same account carrier. No evidence supports changing the CPI function to a borrowed API or changing an account from owned to borrowed.

`carrier_trace.py` symbolically follows the successful path with explicit PDA, comparison, market-cap and memcpy stubs. All 169 initialized carrier bytes have identical input provenance. The remaining fifteen bytes are three five-byte AccountInfo padding holes and are left unspecified. The 184-byte layout consists of a 24-byte empty remaining-accounts Vec, three 48-byte AccountInfos and sixteen bytes for signer seeds. The trace is bounded to the success path and valid non-overflowing reference counts; it does not claim whole-function semantic equivalence. Actual CPI/destructor machine bodies are checked separately.

The exact context bytes therefore do not explain the missing original layout. Remaining differences include context placement/move coalescing and the original dedicated authority Pubkey local. A prior named-authority contextual trial restored the Pubkey copy but grew to 2,312 bytes while retaining the context copy. Prior multi-function scoped/tuple/Return/delayed-construction probes failed baseline calibration (1,968 versus 2,248 bytes); they remain inconclusive. Repeating these spellings or changing clone order would not be a new source-backed hypothesis.

No source patch, attribute, padding, clone-order change or build was made in this review. A useful next proposal needs independently supported ownership or call-site structure that naturally places the early context in outgoing storage. The cached generator source in this packet explains the current API; its inclusion does not establish the original historical source package.
